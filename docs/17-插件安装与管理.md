# 插件安装与管理

在桌面版打开「连接与数据 → 插件 → 添加插件」。原「手动捕获」入口已从插件区移除，新增事项仍通过顶部「新建」使用。

## 安装

输入以下任意一种来源：

- npm 包名，可带版本，例如 `@modelcontextprotocol/server-filesystem`。
- 公开 GitHub 仓库，例如 `https://github.com/owner/repo`，可附 `#分支` 或 `#标签`。下载仓库归档，不依赖本机 Git。
- 本地绝对目录，或点击文件夹按钮选择目录。根目录必须有 `package.json`。

可选 npm 官方源或中国大陆镜像。安装源用于包及依赖下载；GitHub 仓库归档仍从 GitHub 下载。失败时来源和安装源保留，界面显示实际错误；失败的安装不会进入已安装列表。

当前支持已构建的 Node.js MCP 标准输入输出服务：包名、关键词或描述包含 MCP，且只有一个指向 `.js`、`.mjs` 或 `.cjs` 文件的 bin 入口。多个入口或内部命名的包可声明下列格式。

安装不执行 `prepare`、`postinstall` 等生命周期脚本。不支持 Python、原生编译、未构建的 TypeScript 项目、私有仓库或其他应用专用插件。需要构建的插件应先构建到 JavaScript，再从本地项目安装。DeepSeek Harness 等宿主专用包需要适配 MCP，不会只因包下载成功就显示可用。

## 配置和使用

安装后打开管理页：

1. 按插件说明填写「启动参数」，格式为 JSON 字符串数组，例如 `["D:/我的工作文件"]`。
2. 需要密钥时填写「环境变量」，例如 `{"API_KEY":"你的密钥"}`。配置在本机加密保存，重新打开不回显值；留空保留，`{}` 清空。系统运行时变量不能覆盖。
3. 点击「连接插件」。完成 MCP 握手和工具列表读取后才显示已连接；失败会显示协议错误或插件进程输出。
4. 选择工具，查看参数格式，填写 JSON 对象并点击「运行工具」。结果直接显示在管理页。工具当前由用户手动调用，不会因聊天消息或文件内容而自动执行。
5. 「停用」结束本次插件进程；「卸载」需要再次确认，删除安装副本及其配置，保留原始本地目录。

插件以当前用户的本机权限运行，连接前应确认来源可信。重启应用后需手动连接，避免后台自动启动未使用的插件。浏览器预览只能查看界面，本机安装和运行需使用桌面版。

插件安装副本和加密配置位于 `%APPDATA%/Xiaoyu/plugins/`，独立于工作台 SQLite。备份整个应用数据时需同时保留该目录；工作数据 JSON 导出不包含插件密钥。

## 自定义入口

在包根目录添加 `zhixu.plugin.json`，或者在 `package.json` 的 `zhixu` 属性中填写同样内容：

```json
{
  "apiVersion": 1,
  "type": "mcp",
  "entry": "dist/server.js",
  "args": []
}
```

入口必须是插件目录内部真实存在的 JavaScript 文件；跨目录路径和指向目录外部的链接会拒绝。包根目录仍需要包含名称及版本的 `package.json`。

## 验证

`npm test` 包含来源校验、兼容声明、路径越界和目录链接检查。

`npm run test:plugins` 使用隔离的本地测试插件，验证真实安装、忽略生命周期脚本、失败输入保留、连接失败原因、MCP 工具调用、密钥加密及结果隐藏、参数持久化、重启、停用和卸载。该测试不访问用户数据库，也不在用户实际插件目录安装第三方软件。

可选联网检查：`node tests/plugin-registry.smoke.mjs`。它在隔离配置中从官方源安装文件系统 MCP，仅开放专门的测试目录，调用目录列表并卸载。2026-10-24 已在项目目录外的打包程序中通过，实际下载版本为 2.0.0。
