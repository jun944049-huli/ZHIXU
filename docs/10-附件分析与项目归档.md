# 0.1.6 附件分析与项目归档

本文保留 0.1.6 的早期流程记录，以下 20 MB、12 万字及浏览器能力描述不代表当前版本。
当前支持格式、单文件 50 MB 限制、分析与保存步骤请以 [知序操作手册第 8 节](26-知序操作手册.md#8-上传-wordexcelpdfpowerpoint) 为准。

## 上传与解析

对话输入框的加号、项目的“文档”页均可上传。支持 DOC、DOCX、XLSX、PDF、PPTX、TXT、MD、CSV，
每次 1 至 10 个文件，每个不超过 20 MB，单份正文最多 12 万字。
Word、Excel、PDF、PowerPoint 解析在桌面版运行，使用独立解析进程，不需要本机安装 Office。
浏览器预览目前只支持文本附件。

旧版 XLS、PPT 需先另存为 XLSX、PPTX；加密文件须先解除密码；扫描 PDF、图片和截图需先进行 OCR。
不会执行宏、公式或文档中的命令。表格保留行列关系，PDF 和演示文稿保留页码或幻灯片位置。
超限、损坏或缺少正文时显示失败原因，不会伪装为分析成功。

## 分析与归档

上传前可以指定项目、选择分析方式，并填写可保存的通用分析指令。
选择已配置的 AI 时，提取的正文会发送给该供应商进行摘要、任务拆解及信息提取。
本地规则只按行动语句提取候选任务，缺少的信息保留待确认，不负责理解自定义指令。
AI 请求失败或输出不符合结构时，会明确标注回退本地规则。

- 明确指定的已有项目：直接归档附件并生成任务。
- 自动识别时：仅在原文件名和正文中唯一命中一个完整项目名称时自动归档；多项目或未知归属等待确认。
- 新项目：保存为“待确认项目”，不自动创建。选择“创建新项目”，修改项目名与草稿后，点击“创建项目并归档”。
- 任务未指定截止日期时加入今日“可以做”，工时为“待估时”；有日期时安排到对应日期。
- 附件记录可从对话输入框的文件图标、上传弹窗的“附件记录”找到；已归档文件也会出现在项目文档页。

## 修改与来源

摘要、项目归属、通用分析指令及任务标题、负责人、截止日期、优先级、工时均可修改。
已归档附件的“保存修改”会同步现有任务；改变项目归属须点击确认归档。
重复保存不重复建任务，已删除任务不会因再次保存附件而复活。
重新分析已生成任务的附件需要确认，已有任务保留，相同来源合并，新增候选等待保存到项目才生效。
同一份文件重复上传到同一项目时打开已有记录，避免重复拆解。
删除项目时保留附件并转回待确认，原文与原文件不删除。

原文件保存到 `%APPDATA%\Xiaoyu\attachments\`，按内容校验和标识；可通过“导出原文件”恢复上传时的文件。
摘要、解析正文和拆解记录保存在本机 SQLite，编辑分析结果不会改写原 Office/PDF 文件。
SQLite 备份包含正文与分析，不包含单独存放的原文件；完整备份或迁移须退出程序后复制整个用户数据目录。

## 验证

`npm test` 验证真实格式解析、来源标记、损坏与超限文件、原文件校验、项目匹配、AI 输出校验与网络失败回退。
`npm run test:documents` 使用独立桌面测试资料，验证批量上传、自动归档、修改、待确认新项目、重复操作及完整关闭重开后的导出。
`npm run test:interfaces` 回归原有页面、项目页签、报表和备份；`npm run test:web` 检查 390px 与 1440px 的附件编辑窗。
测试不使用日常工作数据。源码、文档、测试与版本包一起同步 HULIKU，本机仍覆盖唯一桌面入口。
