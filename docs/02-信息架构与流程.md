# 小鱼 · 信息架构与关键流程

> 文档版本：v0.3  
> 更新日期：2026-10-21  
> 对应原型：`prototype/`

## 1. 信息架构

```text
小鱼
├─ 对话（chat）
│  ├─ 连续会话（本地记忆）
│  ├─ AI 操作卡
│  ├─ 内容润色
│  ├─ 自定义快捷指令
│  └─ 参考范围 / 模型 / 安全边界
├─ 今日（today）
│  ├─ 产能与承诺
│  ├─ 逾期 / 今日到期
│  ├─ 必须做 / 应该做 / 可以做
│  └─ 等待墙 / 今日会议
├─ 收件箱（inbox）
│  ├─ 待确认输入
│  ├─ 原文
│  └─ AI 草稿
├─ 项目组合（projects）
│  ├─ 项目卡片
│  ├─ 组合时间线
│  └─ 筛选
├─ 项目详情（project）
│  ├─ 概览
│  ├─ 任务
│  ├─ 风险
│  ├─ 项目表（自动润色记录）
│  ├─ 干系人
│  └─ 文档 / 活动
├─ 报表（reports）
│  ├─ 日报 / 周报
│  ├─ 事实层
│  ├─ 叙述层
│  └─ 风险 / 下周计划
├─ 画像（profile）
│  ├─ 时间分配
│  ├─ 承诺模式
│  └─ 可解释结论
└─ 数据与集成（data）
   ├─ 连接器：内容与沟通 / 工作系统 / 插件与扩展
   ├─ 数据健康度
   ├─ 字段管理
   ├─ 我的工作流
   └─ 自动化规则
```

### 1.1 全局框架

- 左侧固定侧边栏：品牌、工作台名称、主导航、项目快捷入口、AI 状态、用户卡片。
- 顶部栏：面包屑、全局搜索、模型状态、快速捕获、通知、主题切换。
- 主内容区：最大宽度 1460px，页面标题 + 内容。
- 弹层：快速捕获、命令面板、插单影响、个人资料、工作流解析。
- 全局 toast：右下 / 底部居中，2.5 秒自动消失。

### 1.2 导航优先级

1. 对话：第一入口，高频指令与执行，带 AI 标识。
2. 今日：每天的清单与产能视图。
3. 收件箱：未确认输入，带数量。
4. 项目：项目经理视角入口。
5. 报表 / 画像 / 数据：低频但重要。

## 2. 页面与状态

| 页面 | 路由状态 | 核心状态 | 主要动作 |
| --- | --- | --- | --- |
| 今日 | `state.view = 'today'` | 任务勾选、产能 | 捕获、插单模拟、进项目 |
| 对话 | `'chat'` | 消息、模型、参考范围、发送中、润色草稿、快捷指令草稿 | 发送、确认、取消、润色、编辑快捷指令 |
| 收件箱 | `'inbox'` | 选中条目 | 确认、改归属、进项目 |
| 项目组合 | `'projects'` | 筛选 | 进项目、看时间线 |
| 项目详情 | `'project'` + `projectId` + `projectTab` | 当前项目、标签页 | 切标签、看风险、看任务 |
| 报表 | `'reports'` | 报表类型、模板 | 切换、复制、打印 |
| 画像 | `'profile'` | 无 | 看依据、关闭建议 |
| 数据与集成 | `'data'` | 字段标签、工作流草稿 | 连接、保存工作流、加字段 |

### 2.1 原型 localStorage

| Key | 内容 | 说明 |
| --- | --- | --- |
| `jw-theme` | `light` / `dark` | 主题偏好 |
| `jw-profile` | 姓名、角色、头像、颜色 | 个人资料；工作台名称由姓名派生 |
| `jw-settings` | DeepSeek API Key 等应用设置 | Key 仅存本机，未配置时润色回退本地规则 |
| `jw-workflow` | 工作流文本、规则、版本 | 我的工作流 |
| `jw-chat-history` | 最近 60 条对话 | 连续记忆；刷新 / 重开仍保留 |
| `jw-chat-model` | 模型选择 | DeepSeek / OpenAI / Ollama |
| `jw-chat-shortcuts` | 快捷指令 | 名称 + 完整指令；点击只填入输入框 |
| `jw-project-notes` | 项目表记录 | 按项目保存原文、润色文本、来源、记录人与时间 |

> Electron 阶段迁移到 SQLite；localStorage 仅保留 UI 偏好。

## 3. 关键流程

### 3.1 早晨开工

```text
打开小鱼
→ 顶部日期控件可切昨天 / 今天 / 明天 / 下周，或指定日期
→ 今日页显示产能条、具体工作时间段与承诺
→ 先看逾期 / 今日到期
→ 按「必须做 → 应该做 → 可以做」推进
→ 勾选完成，产能与计数即时更新
```

设计要点：

- 不要求用户先整理收件箱。
- 逾期与今日到期放在第一屏。
- 任务行只保留决策所需信息，详情进项目页。
- 非今天视图为只读摘要：任务、预计投入、完成情况与工作时间；点「回到今天」恢复编辑。
- 产能卡显示具体时间段，例如 09:00–09:15 站会、09:15–11:15 深度工作，而不只是汇总小时数。

### 3.2 快速捕获

```text
Ctrl + Space
→ 粘贴原文 / 选择来源
→ AI 解析标题、项目、截止、估时、优先级
→ 用户修改草稿
→ 确认加入今日 / 项目 / 等待
```

失败分支：

- 解析失败：保留原文，提示手动填写。
- 项目不明确：进入收件箱，标记“待归属”。
- 时间不明确：不猜测，显示“待确认”。

### 3.3 收件箱确认

```text
收件箱
→ 左侧选择条目
→ 右侧看原文与 AI 草稿
→ 修改归属 / 截止 / 估时
→ 确认
→ 条目离开收件箱，进入今日或项目
```

### 3.4 AI 对话：更新项目进展

```text
用户在对话页输入：
「星火联调已完成 80%，测试库还没开通，帮我更新进展，风险提到高」
→ AI 匹配项目（项目名 / 别名 / 干系人）
→ AI 解析进度 80%
→ 展示操作卡：
   - 匹配项目：星火项目 · 93%
   - 更新任务：整理联调问题 · 35% → 80%
   - 更新风险：测试库开通延迟 · 中 → 高
   - 新增等待：运维开通测试库 · 已等 6 天
→ 用户点「确认执行」
→ 写入项目进度、任务进度、风险等级、等待墙
→ 操作卡标记「已执行」
→ AI 追加结果消息，并提供「写进日报 / 查看今日」
```

关键规则：

- 匹配依据：项目名、项目别名、干系人姓名、当前参考范围。
- 写操作前必须展示变更前后值。
- 提供「只更新进度」降级选项。
- 取消不写入，并明确告知“没有写入”。

### 3.5 AI 对话：把消息拆成任务

```text
输入：
「把王总在飞书说的竞品分析拆成任务，今天 17:00 前给结论」
→ 通过干系人「王总」匹配星火项目
→ 生成任务草稿：
   - 标题：输出竞品分析结论
   - 截止：今天 17:00
   - 估时：1.5h / 2.5h
   - 建议：确认后加入今日推进
→ 确认执行
→ 任务进入「应该做」
```

### 3.6 AI 对话：产能判断

```text
输入：
「今天还能接一个 2 小时的临时任务吗？」
→ 读取今日承诺 6.5h / 7.2h
→ 计算新增后 8.5h，超出 1.3h
→ 指出被挤占的任务与缓冲
→ 给出两个选项：压缩范围 / 改到明天
→ 不写入任何数据
```

### 3.7 生成周报

```text
报表页 / 对话页
→ 选择周报
→ 汇总本周事实：完成、进行中、风险、时间记录
→ AI 生成叙述
→ 用户编辑
→ 复制 / 打印 / 导出
```

事实层与叙述层分离：

- 事实层：结构化、可回到任务 ID。
- 叙述层：可编辑文本，不覆盖事实。

### 3.8 配置个人工作流

```text
数据与集成 → 我的工作流
→ 输入自然语言，例如：
   「开完会 10 分钟内，把行动项提取到收件箱；每条必须有负责人和截止。」
→ AI 解析为规则
→ 用户检查、修改
→ 保存
→ 对话页参考栏显示工作流版本
```

### 3.9 修改个人资料

```text
点击左下角用户卡片
→ 修改姓名 / 角色 / 颜色，头像缩写随姓名自动生成
→ 保存
→ 左上角工作台变为「${姓名}的工作台」
→ 项目负责人、干系人中的本人名称同步
→ 头像缩写同步到侧边栏、对话页与项目成员头像
```

约束：

- 助手名称固定「知序」，不提供编辑入口。
- 不提供“头像缩写”字段，中文取姓名第一个字，英文取首字母（最多两个）。
- 不提供独立“工作区名称”字段。
- 工作台名称只读、自动派生。
- 数据只存本地。

### 3.10 内容润色

```text
对话输入框左下角「润色」
→ 打开润色弹层，默认带入当前输入或最近一条用户消息
→ 选择语气：简洁 / 正式 / 有说服力 / 温和
→ 左侧可编辑原文，右侧实时预览
→ 复制，或「替换输入框」
→ 回到对话，仍需手动发送
```

规则：

- 润色不自动发送。
- 不改变原文中的数字、日期与截止时间。
- 只调整结构与语气，不新增具体事实。
- 原文为空时，使用最近一条用户消息或示例文本。
- 快捷指令行不再重复放「润色一段话」，避免与左下角入口重复。

DeepSeek 接入：

```text
设置 → 填入 DeepSeek API Key → 测试连接 → 保存
→ 打开润色弹层
→ 本地规则先给出预览
→ 调用本地代理 POST /api/polish
→ DeepSeek deepseek-chat 返回润色结果
→ 预览区替换为 DeepSeek 结果
```

- 润色弹层显示当前状态：本地规则 / DeepSeek 润色中 / DeepSeek / 失败回退。
- 未配置 Key、代理未启动或 API 失败时，保留本地规则结果，不阻塞使用。
- Key 只保存在本机浏览器；代理仅监听 `127.0.0.1`，不向局域网开放。
- 提示词要求保留事实、数字、日期、人名、项目名与截止时间，不新增事实。

### 3.11 自定义快捷指令

```text
对话输入区上方 → 快捷指令行最右侧「+ 自定义」
→ 打开快捷指令弹层
→ 编辑：按钮名称 + 完整指令
→ 新增 / 删除 / 恢复默认
→ 保存
→ 快捷指令立即出现在输入框上方
→ 点击只填入输入框，不自动发送
```

规则：

- 默认 4 条：更新项目进展、把消息拆成任务、生成本周周报、检查今天能否接活。
- 名称要短，能一眼看懂；内容是一条完整、可直接发送的指令。
- 快捷指令只做输入加速，不改变 AI 的确认与写入规则。
- 规则保存在本地，刷新后仍生效。
- 模型保持手动选择：DeepSeek / OpenAI / Ollama，不做自动路由。

### 3.12 对话描述自动写入项目表

```text
对话输入一条项目描述
→ 按项目名 / 干系人 / 当前上下文匹配项目
→ 自动润色：去掉口语填充词，统一正式、简洁的表达
→ 写入该项目「项目表」：时间、记录、来源、记录人
→ 对话中出现绿色回执「已自动润色并写入 XX 项目表」
→ 点「查看项目表」直接打开项目详情的项目表标签
```

规则：

- 只在匹配到项目时自动写入；未匹配时不猜测，仍按原对话流程处理。
- 项目表记录属于低风险内容，自动写入；进度、风险、任务等结构性变更仍需确认。
- 原文与润色文本都保留，项目表默认展示润色文本，下方显示原文。
- 项目详情提供「用对话记录」按钮，点击回到对话并带入当前项目上下文。
- 记录保存在 `jw-project-notes`，刷新后仍保留。

## 4. 交互规范

### 4.1 键盘

| 快捷键 | 动作 |
| --- | --- |
| `Ctrl + K` | 打开命令面板 |
| `Ctrl + Space` | 快速捕获 |
| `Enter` | 对话发送 / 命令面板执行 |
| `Shift + Enter` | 对话换行 |
| `Esc` | 关闭弹层 |

### 4.2 确认与撤销

- AI 结构性写操作：先预览，再确认。
- 项目表记录：匹配到项目后自动写入，可在项目表追溯原文与润色文本。
- 外部同步写操作：默认关闭，需显式授权。
- 破坏性操作：二次确认。
- v1 至少支持“取消未执行”；v1.1 增加“撤销已执行”。

### 4.3 空状态

| 场景 | 文案方向 |
| --- | --- |
| 今日无任务 | “今天没有必须做的事。要不要从收件箱挑一件？” |
| 收件箱为空 | “没有待确认的输入。捕获一件试试。” |
| 对话无消息 | 显示欢迎语与三条示例指令 |
| 项目无风险 | “当前没有登记风险。” |
| 连接器未连接 | “未连接。连接后自动同步最近 30 天。” |

### 4.4 错误状态

- AI 超时：保留用户输入，提供“重试”。
- 模型不可用：提示切换模型，不丢草稿。
- 同步失败：显示失败原因与重试入口。
- 解析置信度低：显示备选项，要求用户确认。

## 5. 数据模型（面向实现）

### 5.1 核心表

```text
project(id, name, owner_id, stage, health, progress, start_at, due_at, created_at)
task(id, project_id, title, status, priority, estimate_p50, estimate_p90, due_at, progress, source_id)
waiting(id, project_id, title, person, days, impact, status)
inbox_item(id, source_id, raw_text, parsed_json, project_id, confidence, status)
source_item(id, connector_id, external_id, author, raw_text, occurred_at)
risk(id, project_id, title, probability, impact, level, owner, action, status)
project_note(id, project_id, raw_text, polished_text, source, author_id, occurred_at, created_at)
report(id, kind, period_start, period_end, facts_json, narrative, status)
profile_snapshot(id, period, metrics_json, insights_json)
workflow(id, text, rules_json, version, updated_at)
chat_thread(id, title, model, context_json, created_at)
chat_message(id, thread_id, role, content, action_json, created_at)
chat_action(id, message_id, type, target_type, target_id, diff_json, status)
```

### 5.2 扩展表

```text
custom_field(id, entity_type, key, label, field_type, options_json, enabled)
custom_value(entity_type, entity_id, field_id, value_json)
relation(id, from_type, from_id, to_type, to_id, relation_type)
connector(id, key, group, name, status, config_json, last_sync_at)
automation_rule(id, name, trigger_json, action_json, enabled)
```

### 5.3 设计约束

- 不在 `project` / `task` 表里为每个集成加列。
- 外部原始数据必须保留在 `source_item`。
- AI 操作以 `diff_json` 记录变更前后值，便于审计与撤销。
- 自定义字段用 `value_json`，不频繁改表结构。

## 6. 事件与埋点（建议）

| 事件 | 属性 | 用途 |
| --- | --- | --- |
| `task.completed` | project_id, estimate, due | 承诺兑现率 |
| `capture.created` | source, parse_confidence | 捕获效率 |
| `inbox.confirmed` | project_id, edited_fields | AI 解析质量 |
| `chat.sent` | model, context | 对话使用率 |
| `chat.action_previewed` | type, target_type | 建议覆盖率 |
| `chat.action_applied` | type, changed_fields | 确认率 |
| `chat.action_cancelled` | type | 预览准确度 |
| `report.generated` | kind, facts_count | 报表效率 |
| `workflow.saved` | rules_count | 工作流采用 |
| `connector.connected` | connector_key | 集成进度 |

> 本地优先产品默认不上传埋点；以上事件先写本地日志，用户可选择导出。

## 7. Electron 迁移映射

| 原型 | Electron |
| --- | --- |
| `DB` 全局对象 | Drizzle schema + SQLite |
| `state` 内存态 | Zustand / Jotai |
| `renderX()` 字符串模板 | React 组件 |
| `data-action` 事件委托 | 组件事件 / command handlers |
| `localStorage` | `settings` 表 + 少量 UI 偏好 |
| 模拟 AI 回复 | Vercel AI SDK + provider 路由 |
| 模拟操作卡 | `chat_action` + diff 预览组件 |
| `python http.server` | electron-vite dev server |

建议目录：

```text
src/
├─ main/            # Electron 主进程、SQLite、IPC
├─ preload/         # 安全桥
├─ renderer/
│  ├─ app/          # 路由与布局
│  ├─ features/     # today, chat, inbox, projects, reports, profile, data
│  ├─ components/   # 设计系统组件
│  └─ lib/          # AI、格式化、匹配
└─ shared/          # 类型、schema、常量
```
