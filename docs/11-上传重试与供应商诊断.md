# 上传重试与供应商诊断

版本：0.1.7，2026-10-22。

本文记录 0.1.7 的范围。0.1.8 已将单文件上限升级为 50 MB，新增解析失败原文件保留、重新解析及真实模型对话，见 [当前版本说明](12-50MB上传与模型对话.md)。

## 上传

- 修复原来任何文件失败后直接打开附件记录、销毁文件选择框的问题。
- 失败时停留在原窗口，保留原文件选择、项目、分析方式和指令，逐项显示文件名、状态及原因。
- “重试失败文件”只处理失败项；成功项跳过，不重复写入附件或生成任务。
- 支持部分成功、全部失败及临时保存故障恢复。重新选择文件会重置本次结果。
- 可区分空文件、超过 20 MB、格式不支持、后缀与内容不匹配、加密文件、扫描 PDF、解析超时、规模限制、解析组件和本地磁盘写入问题。
- 文本读取支持 UTF-8、带 BOM 的 UTF-16 和 GB18030。GB18030 会提示核对字符。
- 原文件先保存再进行 AI 分析；AI 失败不会丢失原文件，改用本地规则，并显示具体供应商或响应格式错误，可重新分析。
- 新项目仍等待明确确认，不因上传或诊断自动创建。

排查边界：标准 DOCX、XLSX、PDF、PPTX、Markdown 的实际桌面包上传测试通过。本次未取得用户上传失败的原文件，不能据此断言其特定文件的失败原因；新版会在原窗口给出解析或存储原因，便于进一步定位。

## 自定义供应商

入口：左下角个人资料与设置 → 自定义供应商。

1. 填入 API Base URL 与 API Key，停止输入约 1 秒后自动获取模型；也可点击“获取模型”。
2. 默认选取列表中第一个名称未标示为图片、语音、嵌入或重排的模型，用户仍需确认该模型适合文本任务；所有返回模型均可选择。
3. 供应商禁用模型列表时，保留手动填写模型的入口。已有手填值不会被新列表覆盖。
4. 点击“诊断供应商”查看配置、模型列表、真实请求和建议。真实请求仅发送简短测试文本，可能产生少量费用。
5. 诊断通过后将实际成功协议填入设置，点击保存，用于润色和附件分析。更改地址、密钥、模型或协议会立即使旧诊断失效。

支持 OpenAI 兼容的 `GET /models`、`POST /chat/completions` 和 `POST /responses`。自动处理根地址、`/v1` 前缀及已填写的完整模型/生成接口；根地址先尝试 `/v1`，不存在时尝试不带前缀的接口。显式协议不做协议切换；自动协议仅在 HTTP 404、405、501 时尝试其他协议或路径。401、403、429 和服务异常不会被当作路径错误反复切换。

模型列表通过不能证明模型可以实际生成文本，因此诊断还会发送真实请求。HTTP 200 但返回网页、空文本、拒绝或截断内容均不会显示通过。模型列表无权限而手填模型的实际请求成功时，报告会显示“列表需留意、真实请求通过”。

## 错误展示

报告显示实际请求路径、耗时和生成请求 HTTP 状态；失败区分鉴权、权限、余额、接口/模型、限流、服务端错误、超时、DNS、拒绝连接、连接中断及 TLS 校验。

供应商 JSON 中的错误说明会脱敏后展示，不展示 API Key 或完整成功响应。HTTP(S) 以外的协议、地址内嵌账户、重定向被拒绝；请求有超时和响应体积上限。凭据继续使用系统安全存储加密。

目前仅桌面版提供模型自动获取和诊断。浏览器预览会明确提示使用桌面版；浏览器原有 Python 润色代理未增加 Responses 或模型诊断接口。完整自由模型对话、原生 Anthropic/Gemini 协议、OCR 和后台自动同步不在此版本范围内。

## 验证

- `npm test`：解析、原附件保存、项目归属、任务拆解、两种生成协议、模型列表、鉴权脱敏、错误网页、超时、截断和本地回退等测试。
- `npm run test:documents`：真实文档上传、失败后保留 FileList、混合批次重试不重复、临时持久化失败重试成功、项目确认及重启导出。
- `npm run test:providers`：实际 Electron 窗口中自动获取模型、Responses 识别、401/403 原因、保存后润色及附件分析、密钥加密与重启恢复。
- `npm run test:interfaces`：7 个页面、6 个项目页签、6 类报表、文件导出与数据库备份。
- `npm run test:web`：390px 和 1440px 的附件、模型选择及诊断报告布局。诊断布局使用模拟桥接，实际网络由桌面专项验证。

所有测试使用独立临时配置和本机服务，不读取或修改真实用户项目与凭据。
